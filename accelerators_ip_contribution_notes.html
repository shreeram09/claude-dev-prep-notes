Module 5 · where code starts working is where reusable, deployable, auditable work begins

Throughline: a build that works is not yet a build that survives reuse, review, or deployment. Package while fresh, verify for maintainers, pin versions, defend platform residency, and guard every seam.

1 · Packaging a Working Build for Reuse (Accelerators)

An accelerator separates engagement-specific values from the reusable core and exposes them as documented parameters with defaults — next team configures instead of editing the loop.

① Agent Template
System prompt + tool schemas + loop. Parameterize domain values (paths, prompts, scopes, thresholds).
② MCP Server Pkg
Exposes tools + documented inputs. Installing team sets scope & credential refs without code edits.
③ Portable Eval Suite
Dataset + rubric shipped together. Proves asset works in new context & gates model promotion.
  • Document assumptions: environment prereqs, expected inputs, handled failure modes, and the bundled eval baseline.
  • Bundle the audit log: record data touched, identity acted under, and actions taken so regulated reviews pass.

4 · Deployment Platforms & Versioning What Ships

The same Claude model can run on 6 deployment platforms, differing in identity, data residency, latency, and billing:

  • First-Party Claude API (Anthropic API key; quickest direct access, newest features first).
  • Claude Platform on AWS · Claude in Amazon Bedrock (AWS IAM identity, VPC/CloudTrail, AWS compliance boundary) · Claude on Bedrock (legacy).
  • Google Vertex AI (GCP IAM identity, GCP residency & billing boundary) · Third-party platforms.

5 · Comparing Platforms: Latency, Compliance & Cost

  • Latency: measure from the customer's deployment region, NEVER from your dev laptop (180ms laptop trace hid an EU residency violation!). Regional vs global endpoints trade residency against capacity routing.
  • Compliance & Data Residency: for regulated customers, residency is pass/fail (hard gate, not a trade-off). Pick the platform where the customer already holds its compliance posture & regional boundary.
  • Cost: compare total cost per call (input/output tokens + caching discount + batch discount + platform egress/overhead), not raw token price alone.
Checkpoint 6 Trace: rejected on EU residency → remeasure from EU-west & switch to EU-resident platform!

6 · Multi-Component Apps & Trust Boundaries

When an app chains components across environments (API → Claude Code task → MCP server), the app is only as contained as its weakest seam. Trust does NOT carry over from the sending component!

  • Seam 1 (Untrusted Content Boundary): wrap fetched output with treat_as_data(fetched) so the next component never executes embedded instructions.
  • Seam 2 (Most Privileged Component): scope the MCP server to least_privilege_read_only (never full_access). If a seam cannot be secured programmatically, assign a human approval gate.
Passing fetched content straight into next_call() lets a web page drive your DB!
