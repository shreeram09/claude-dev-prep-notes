Production Engineering, Evals & Security

Module 4 · proving an agent that works in dev holds up under real production traffic

Theme: development hides the failures that production reveals. Write a 1-page design doc BEFORE code: ① success criteria (eval) · ② failure handling · ③ cost/latency budget · ④ trust boundary.

1 · Evals & Calibrated Judges

An eval turns “done” from a feeling after 3 manual demos into a tracked score on a holdout set. Write the eval before implementation so you don't rationalize model output.

Change 1 thing at a time (prompt OR tool OR model) so you know what moved the score.

Matching the Grader to the Output Shape

① Exact / String Match
1 correct form (label, ID, fixed value). ~0 cost, runs on every commit. Fails on any paraphrase.
② Code-Graded Check
Structural rule: json.loads, ast.parse, regex, range, required keys. Cheap & deterministic.
③ LLM-as-Judge
Open-ended quality (faithful summary, tone, rationale). Costs 1 API call/case + noisy → schedule slower pass.

Building & Calibrating an LLM-as-Judge

  • Judge prompt MUST require {"strengths", "weaknesses", "reasoning", "score"} (reasoning before score improves reliability) + an anchored score scale: 1–3 misses required content · 4–7 partial · 8–10 complete & faithful.
  • Calibrate before trusting: human-score 20–50 cases across full range → run judge → compare agreement → refine rubric until aligned.
  • expected_behavior must name the concrete output (e.g., “lists all 3 action items + owners”), NEVER restate the input (“summarize transcript”).
Unanchored rubric → judge drifts to a safe ~6 on everything!
Postmortem – Passed every check, extracted wrong value: Invoice extractor checked only valid JSON + 3 manual happy-path PDFs. Multi-page credit-memo PDF arrived → extracted credit total instead of invoice total. Fix: code check for structure + semantic accuracy check against labeled multi-page edge cases.

2 · Testing Pyramid & Request Tracing

Each test level catches a failure the others miss. Most silent AI failures hide at the integration seam where two passing components hand off.

Tracing & Retrieval Routing (Fetch-Once vs Agentic Search)

  • Trace = structured per-step record (request_id, step, input, output, tokens, latency_ms, status) → localizes which step broke in seconds.
  • Fetch-once (RAG): 1 retrieval call → inject → 1 model call. Low cost/latency; best for single-fact lookups on stable corpora.
  • Agentic search: model issues queries, reads results, refines across rounds. High token/latency cost; best for multi-step synthesis or fast-changing repos.
  • Route between them: default to fetch-once; escalate to agentic search only when query signal requires multi-hop exploration.
Green unit + green functional + red E2E = broken integration seam!

3 · Surviving Production Failures & Model Selection

Every failure starts with one question: will waiting and sending the exact same request again succeed?

Retriable (Transient)
429 Rate Limit · 500 Internal · 529 Overloaded · network timeout.
✔ Honor retry-after header first, else exponential backoff + jitter + cap + budget.
Terminal (Permanent)
400 Bad Request · 401 Auth · 403 Permission · 404 Not Found.
✘ Fail fast! Retrying burns budget & hides bug. Route to named fallback/log.
  • Know what the SDK covers: Anthropic SDK automatically retries transient 429/5xx a small fixed number of times. Don't wrap a naive time.sleep(0) loop around it (multiplies retries & deepens rate limit!).
  • Tool errors must come back explicitly: return tool_result with is_error: True + error text so Claude can recover. Never return "" or [] (Claude mistakes empty error for “no results found” data!).
time.sleep(0) on a 429 hammers the rate limit and takes the whole request down!
Checkpoint 3 Retry Pattern: catch RateLimitError → use e.response.headers.get("retry-after") or min(cap, 2**attempt) + random.uniform(0,1); catch APIStatusError → if not is_retriable(e.status_code): raise.

4 · Cost, Latency & Multi-Agent Orchestration

You can't budget what you don't measure: log input_tokens, output_tokens, cache_read, latency_ms, status per call. Reliability has a floor (defined by your eval) — only optimize cost above that floor.

5 Budget Levers
① Model tier · ② Prompt/context trim · ③ Fewer tool rounds · ④ Stream (perceived latency) vs Batch · ⑤ Prompt caching.
Prompt Caching + Batches API
Cache stable prefix (tools → system → messages) for up to ~90% read discount; Message Batches API = async up to 24h for ~50% cost cut (stack both!).
Streaming improves perceived speed (TTFT), NOT total token cost!

Orchestrator-Worker Fan-Out = ~15× Token Multiplier

Checkpoint 4 Match: ① Single-fact lookup → C (fetch-once + smallest model) · ② Broad research splitting into independent parts → A (orchestrator-worker parallel fan-out) · ③ User-facing instant reply → D (streaming) · ④ Cost-sensitive non-urgent job → B (Batches API + prompt caching).

5 · Security, Guardrails & Regulated Reviews

  • Prompt Injection vs Jailbreak: Jailbreak = user tries to bypass safety policy. Prompt Injection = untrusted external content (web page, ticket, repo file, tool output) carries hidden instructions aimed at the agent. Same defense shape!
  • Model reads the whole context as one stream of tokens — no built-in wall between trusted instructions and untrusted data. Trusting your own employees doesn't stop indirect injection!
  • Defense-in-depth layers:
    ① Treat untrusted input as data (delimit/wrap, strip instructions).
    ② Least-privilege identity & scoped secrets (os.environ["API_KEY"], never inline in config; explicit filesystem deny_paths: ["/etc", "/secrets", "~/.aws"]).
    ③ Hook-based guardrail (PreToolUse): runs before write_file / shell executes; blocks any path outside /workspace/output (enforcement, not convention!).
    ④ Audit log + OS sandboxing: log every privileged action (log_audit(action, path, result)) + container/OS sandbox as residual control.
Fetched page had hidden HTML comment: wrote to /workspace/config/settings.json! Block with PreToolUse hook.

6 · Cumulative Production-Hardening Task

Real production failures stack across layers. Diagnose the 3 planted defects and assemble the hardened version:

✘ Broken Prototype (As Shipped) 
def answer(question, page_url):
    page = fetch(page_url) # untrusted!
    notes = read_file("/workspace/input/notes")
    # Defect 3: untrusted destination path!
    write_file(page.suggested_path,
               summarize(page))
    resp = None
    for i in range(5):
        try:
            resp = client.messages.create(...)
            break
        except Exception:
            # Defect 2: instant retry on ALL errs!
            time.sleep(0)
    # Defect 1: 0 eval / holdout set!
    return resp.content[0].text
✔ Production-Hardened Version 
def answer(question, page_url):
    page = fetch(page_url) # still untrusted
    notes = read_file("/workspace/input/notes")
    # Fix 3: fixed path + PreToolUse hook + audit
    write_file("/workspace/output/summary.txt",
               summarize(page))
    # Fix 2: backoff, retry-after, fail fast 4xx
    resp = call_with_retry(
        lambda: client.messages.create(
            model=MODEL, max_tokens=MAX_TOKENS,
            messages=msg(question)))
    # Fix 1: graded holdout eval run on every change
    return resp.content[0].text
Layer 1 · Eval / Test
No graded holdout set existed (only 3 manual demo runs) → add dataset + calibrated rubric run on every change.
Layer 2 · Error / Cost
time.sleep(0) + catching Exception retries terminal 400s & deepens 429s → use call_with_retry().
Layer 3 · Security
page.suggested_path lets fetched content pick write path → hardcode /workspace/output/… + PreToolUse hook.

7 · Reference Tables & Glossary Quick-Look

Error-Handling Decision Table
  • 429 RateLimitError → Retriable; honor retry-after, else exp backoff + jitter.
  • 500 / 529 Overloaded → Retriable; exp backoff up to cap + retry budget.
  • 400 / 401 / 403 / 404 → Terminal; raise immediately, log & alert.
  • Tool exception → Return tool_result(is_error=True) to model.
Regulated Review Defense Checklist
  • Input boundary: wrap untrusted data; separate from system instructions.
  • Identity & secrets: least privilege IAM; secrets in env/vault, never git.
  • Action enforcement: PreToolUse hook blocks out-of-scope writes before execution.
  • Evidence trail: deterministic audit log + OS/container sandbox.

Cheat-sheet: 5 Module Takeaways

① Set the standard before you build: write the design doc & eval first; match grader to output shape (match / code / calibrated judge) · ② Test the seam & trace every step: unit + functional pass while integration handoff breaks; trace logs pinpoint the step · ③ Sort retriable vs terminal: backoff + retry-after on 429/5xx, fail fast on 4xx, pass tool failures via is_error=True · ④ Instrument per-call budget: cache stable prefixes, batch offline jobs (~50% off), fan out subagents (~15× tokens) ONLY when work truly parallelizes · ⑤ Enforce boundaries with hooks: treat fetched content as data, scope credentials, and gate writes with PreToolUse hooks + audit logs.
