MSO Foundations — How LLMs Behave & Reach Us

Module 1 · tokens, context budget, sampling, model tiers & API transport mechanics

Before writing code against Claude, get the mental model right: what the API meters, why outputs vary, how model tiers & reasoning compose, and which transport pattern fits your workload.

1 · Tokens & the Context Window Budget

  • Tokens = unit of input, output & cost (not words/chars). Chars-per-token varies by model tokenizer.
  • Everything counts: system prompt + history + injected docs + tool defs + tool results + model output.
  • Context window = fixed token budget holding the entire request + response at once.
Window never auto-expands or silently drops turns! App must trim / summarise history.

2 · Sampling & Non-Determinism

At each step Claude produces a probability distribution over next tokens and samples from it → identical prompts can return different wording even when both answers are right.

  • Low temp (→ 0): concentrates probability on top tokens → more repeatable (needed for classifiers), still NOT guaranteed deterministic.
  • High temp: flattens distribution → more varied wording/labels.
  • Newest Claude models reject non-default sampling params (temperature, top_p, top_k → 400 error); steer via prompting instead.
Never assert exact string equality on open text! Assert properties/schema or run an eval judge.

3 · Model Family Tiers vs Reasoning Modes

Two independent, composable levers: which model runs (capability tier) ⟂ whether it thinks per request.

Adaptive thinking (per-call): model decides when/how much to think; tune depth with effort (old budget_tokens is deprecated → 400 error on newest models). Thinking content is omitted by default (request summarized display if needed). Earns cost on multi-step logic; wasted on lookups/classifiers.

4 · Prompting Modes: Zero-Shot, One-Shot, Multi-Shot

How many worked input → output examples sit inside the prompt (examples are not training data; they show exact shape in context).

Zero-shot
Instruction only, 0 examples. Cheapest; use when task is simple & shape is obvious.
One-shot
1 input/output pair. Anchors basic formatting quickly.
Multi-shot (few-shot)
2–3+ pairs. Fixes invented structure, casing, or tricky edge cases faster than more prose.
  • Cost/Quality trade-off: every example adds input tokens on every call & eats context window.
  • Interacts with model tier: a few examples often let a smaller, cheaper model (Haiku/Sonnet) match a structure that otherwise needed a larger model zero-shot.
Zero-shot works? Adding 3 examples just burns tokens for ~0 gain!

5 · Reaching Claude: SDK vs REST & Request Shapes

Raw REST (HTTP endpoint + API key + JSON body) vs Official SDK (Python / TS thin wrapper over the exact same REST API — handles auth, request building, default retries, parsing).

TS SDK standard client is already Promise-based (no separate Async class).

6 · Exam Scenarios & Quiz Playbook

Q: Identical prompts = identical text?
✘ No — model samples next token from probability distribution; wording varies even when both are right.
Q: Model choice vs reasoning mode?
✔ Separate levers: model picks family tier; extended/adaptive thinking is a per-call setting.
Scenario: Classifier temp 0 vs high temp
Temp 0 concentrates probability (repeatable label, still not 100% deterministic). High temp spreads distribution (labels drift).
Scenario: Wrong output structure in zero-shot
Switch to multi-shot (2–3 input/output pairs) to show exact structure; add fewest examples that pass eval.
Scenario: 50,000 docs overnight, no user waiting
Use Message Batches API + polling (lower cost, avoids sync rate-limit walls; streaming buys nothing).
Scenario: Long multi-turn agent failing in prod
Context window fixed budget fills up → input error or model_context_window_exceeded truncation. Trim/summarise!

Cheat-sheet: 5 Core Takeaways

① Budget in tokens, not words — prompt, history, tools, and output all share the meter · ② Context window is fixed — oversized input fails upfront; hitting ceiling mid-gen returns model_context_window_exceeded · ③ Sampling = non-deterministic — test structure/properties & grade quality with evals, never exact string match on prose · ④ Model tier ⟂ thinking ⟂ few-shot — start w/ Sonnet + simplest prompt, prove changes on an eval · ⑤ Match transport to listener — Stream for humans, Async for concurrency, Batch for offline bulk.
